## 1. 무엇을 배우고 무엇을 만들까

작은 실습을 연결해, 보고 판단하고 움직이는 가상 로봇 시스템을 만듭니다.

웹 프런트엔드 경험을 출발점으로 삼아 Python·센서·영상·로봇 통신·제어를 연결합니다. 마지막에는 가상 로봇의 작업을 웹 화면에서 살펴보고, 실패 원인을 코드와 기록으로 설명하는 것이 목표입니다.

### 완성한 뒤 보여줄 수 있는 것

**작동하는 코드**

센서 값을 다루고, 위치를 계산하고, 로봇 프로그램끼리 데이터를 주고받습니다.

**설명 가능한 데모**

동작 영상뿐 아니라 시험 조건, 성공·실패 기록, 원인과 수정 내용을 남깁니다.

**운영하는 화면**

프런트엔드 경험을 살려 작업 상태·알림·로그를 보여주는 웹 화면을 만듭니다.

현재 상태  첫 센서 필터 과제는 아직 평가 전입니다. 수강 경험과 실제 숙련은 구분하며, 이 로드맵의 역량을 이미 갖췄다고 표시하지 않습니다.

## 3. 코드와 데이터와 로봇 통신 연결하기

센서 값을 읽고 다루는 작은 실습부터 시작합니다. 이미 가능한 기초는 반복하지 않습니다.

도식  입력과 배열 → 좌표와 통신 → 영상과 AI의 입출력

### 1A  코드와 환경

Python 함수·객체·NumPy 배열, 필요한 Git·명령줄 사용. 배열은 숫자가 모인 표처럼 이해합니다.

결과물  입력 처리 함수와 테스트, 실행 명령. 서로 다른 입력을 시험하고 출력이 달라진 이유를 설명합니다.

### 1B  위치와 프로그램 연결

벡터·행렬·좌표 변환, ROS2 노드·토픽. 노드는 작은 프로그램, 토픽은 데이터를 전하는 방송 채널과 비슷합니다.

결과물  좌표 변환 테스트와 두 노드의 송신·수신 로그. 필요에 따라 요청·응답과 긴 작업 관리도 익힙니다.

### 1C  영상과 AI의 역할

OpenCV·카메라 보정·자세 추정과 AI 역할. LLM은 글, CNN은 영상 특징, VLM은 영상과 글, VLA는 행동까지 연결합니다.

결과물  검출 결과 이미지와 실패 예시, AI 출력의 형식·범위 검증 기록. 큰 모델 학습을 시작 조건으로 삼지 않습니다.

쌓을 역량  입력·처리·출력을 나누고, 배열과 좌표를 다루며, 프로그램 사이의 데이터 흐름을 설명합니다.

확인 기준  작은 입력을 바꿔 실행하고 이유를 설명합니다. 테스트·실행 기록이 있는 부분은 생략하고, 실패한 항목만 보완합니다.

## 4. 물체를 보고 가상 로봇 움직이기

기반: 배열·좌표 변환·ROS2 메시지 전달. 부족한 항목만 짧게 보완하고 들어갑니다.

도식  화면 속 물체 위치 → 좌표 기준 맞추기 → 가상 로봇 명령

**배울 내용**

영상에서 물체를 찾고, 카메라와 로봇의 좌표 기준을 맞춥니다. 목표 위치와 실제 위치의 차이를 줄이는 제어를 익힙니다.

**만들 결과물**

짧은 추적 영상, 위치 오차·처리 지연 기록, 물체를 놓쳤을 때 멈추는 코드와 시험 결과.

**쌓을 역량**

영상 인식과 제어를 연결하고, 문제가 영상·좌표·제어 중 어디서 생겼는지 찾아 고칩니다.

**확인 기준**

정상 추적과 물체 놓침을 각각 시험합니다. 입력을 바꿔도 재현되는지 확인하고, 안전 정지가 실패하면 다음 단계로 넘기지 않습니다.

핵심 구분  픽셀의 위치는 로봇이 이동할 거리와 다릅니다. 깊이 정보, 단위, 좌표축, 필요한 가정을 확인합니다.

통과 증거가 이미 있으면 해당 기초 강의를 생략합니다. 실물 모터 시험은 장비와 안전 조건을 확인한 뒤 별도로 결정합니다.

기반: 좌표·통신·제어·안전 정지·로그 읽기. 가상 환경에서 이동을 먼저 완성합니다.

지도와 내 위치 찾기  
방을 걸으며 약도 그리기  
기술 이름: SLAM

도구 이름: Nav2

도식  출발점에서 장애물을 피해 목표 지점으로 이동

**배울 내용**

지도·자기 위치 추정·경로 계획을 연결합니다. 기본 이동 후, 시범 따라 배우기와 AI 판단을 작은 입출력 실험으로 다룹니다.

**만들 결과물**

가상 물류 이동 데모, 성공·실패 기록, 같은 조건의 규칙 방식과 AI 방식 비교표.

**쌓을 역량**

주행 문제와 AI 문제를 구분하고, 학습에 쓰지 않은 예시에서도 동작을 평가합니다.

**확인 기준**

목표 이동·길 막힘·위치 추정 실패를 각각 시험합니다. 안전 정지와 실패 기록을 남기고, AI 출력은 실행 전에 형식·허용 범위를 검사합니다.

큰 모델 학습이나 GPU 구매는 기본 전제가 아닙니다. 간단한 방식으로 기준 성능을 만든 뒤 필요한 범위만 확장합니다.

## 6. 여러 로봇의 일을 겹치지 않게 나누기

기반: 한 로봇의 실행·취소·완료 상태를 이해하고, 실패를 기록할 수 있어야 합니다.

도식  작업 목록 → 작업 배정 → 로봇 A의 이동과 로봇 B의 집기·놓기

**배울 내용**

작업 배정, 자원 공유, 실행 순서, 집기·놓기, 실패 후 재시도를 익힙니다. 여러 사람이 같은 도구를 쓰는 순서를 정하는 것과 비슷합니다.

**만들 결과물**

두 가상 로봇의 작업 데모, 작업별 상태표, 중복·충돌·재시도 시험 기록.

**쌓을 역량**

하나의 기능을 여러 작업으로 확장하고, 누가 무엇을 하는지와 실패 뒤의 처리 순서를 설계합니다.

**확인 기준**

같은 작업을 중복 실행하지 않는지, 한 자원을 동시에 점유하지 않는지 확인합니다. 실패 후 다시 시작해도 상태가 맞아야 합니다.

### 상태를 따라가면 실패 지점이 보입니다

도식  대기 → 진행 → 완료 또는 실패 후 복구

### 포트폴리오에 남길 묶음

| 결과물 | 보여줄 수 있는 역량 |
|---|---|
| 실행 가능한 코드 | Python·ROS2·비전·제어·웹 연결 |
| 설명서와 환경 기록 | 설치 조건·실행 순서·재현 방법 설명 |
| 테스트와 실패 기록 | 정상·실패·경계 상황을 나눠 검증 |

최종 확인  실행 안내만 보고 다시 돌릴 수 있는가, 실패 상황에서도 상태가 설명되는가, 같은 조건의 성능 비교가 있는가, 핵심 코드를 스스로 바꾸고 설명할 수 있는가를 함께 봅니다.

수치 목표는 각 실습의 장비·조건을 정할 때 합의합니다. 안전 정지·잘못된 명령 차단은 필수입니다. 이 계획만으로 현장 안전 인증이나 취업 준비 완료를 주장하지 않습니다.

첨부 사진과 공식 페이지에서 원본 5단계와 주차를 확인했습니다. 작은 글씨가 흐린 사진의 세부 문장을 정확히 전사했다고 주장하지 않습니다. 단계별 실습·결과물·역량·확인 기준은 개인 학습 제안입니다.

원본의 1-5주차 세부 구간은 1-2, 3-4, 4-5주차로 표기되어 4주차가 겹칩니다. 사진 밖의 30-38주차 기업 프로젝트와 39-41주차 취업 준비는 이번 개인 계획에 자동 추가하지 않았습니다.
